ISSUE-07 Run Unified Multi-Domain Structure Comparison

coding agent が domain を省略した一回の command で Python、SQLAlchemy、Next の適用可否・成功・不完全を区別し、成功 Artifact を保持した集約 manifest と正しい exit code を得られる。

ISSUE-07 は package stable key です。actual SpecDock issue ID は adoption 時に割り当てられ、baseline に production path/symbol は未実装です。
図を読み込んでいます。

この資料で理解できること

この HTML だけで、対象 scope の目的、責務、正常時と失敗時の動作、データと出力、実装順、検証、対象外を把握できます。Requirement、Design、Plan の要約ではなく、新規参加者向けに契約を一続きで説明する specification Artifact です。

製品が HTML report を生成する機能ではありません。ブラウザ内 PlantUML は、この仕様説明の理解を助けるためだけに使用します。

背景と解決したい問題

  • coding agent として、repository の複数 domain を一度に調査し、一部 adapter が失敗しても利用可能な JSON/PlantUML を失わず、人間へ説明できる provenance と diagnostic を受け取りたい。
  • この Issue は all / snapshot-and-diff orchestration を一つの observable acceptance boundary として所有します。
  • declared dependency は ISSUE-04, ISSUE-06。unfinished sibling の内部実装へ依存しません。
  • 複数 adapter の failure isolation、atomic output、aggregate manifest、public exit code、cross-platform packaging を統合し、運用上の blast radius と回復難度が高いため strict を選ぶ。

正常時の処理

      
    
        
  1. 利用者が次の command boundary を使います: code-structure-viz diff --repo . --output-dir /tmp/csv-all-diff
  2. diff で domain 無指定なら python、sqlalchemy、next を deterministic order で実行する。snapshot も同じ default を採用し、明示 domain で絞り込める。
  3. common envelope は run/domain status、artifact descriptor、diagnostic、coverage、graph primitive だけを共有し、domain identity/member/relation/matching を統一 model へ押し込まない。
  4. format 未指定時は complete/incomplete domain ごとに versioned semantic JSON と domain-specific PlantUML を生成する。not_applicable domain は status/diagnostic のみ。
  5. I07-AT-001 を含む acceptance suite で observable result を確認します。
