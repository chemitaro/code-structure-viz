ISSUE-05 Generate Next.js Component Snapshots

coding agent が first-party TypeScript adapter を通じ、Next.js repository の module、exported component、props、static relation、client boundary を JSON と PlantUML で取得できる。

ISSUE-05 は package stable key です。actual SpecDock issue ID は adoption 時に割り当てられ、baseline に production path/symbol は未実装です。
図を読み込んでいます。

この資料で理解できること

この HTML だけで、対象 scope の目的、責務、正常時と失敗時の動作、データと出力、実装順、検証、対象外を把握できます。Requirement、Design、Plan の要約ではなく、新規参加者向けに契約を一続きで説明する specification Artifact です。

製品が HTML report を生成する機能ではありません。ブラウザ内 PlantUML は、この仕様説明の理解を助けるためだけに使用します。

背景と解決したい問題

  • coding agent として、Next.js application を build/execute せず、TypeScript compiler の静的意味情報から component structure と server/client boundary を把握したい。
  • この Issue は next / snapshot を一つの observable acceptance boundary として所有します。
  • declared dependency は ISSUE-01。unfinished sibling の内部実装へ依存しません。
  • cross-runtime versioned protocol、optional dependency、TypeScript semantic boundary、static-analysis security contract を導入し、compatibility failure の回復が難しいため strict を選ぶ。

正常時の処理

      
    
        
  1. 利用者が次の command boundary を使います: code-structure-viz snapshot --repo . --domain next --output-dir /tmp/csv-next-snapshot
  2. Python core は repository-owned Node bridge を明示 protocol で起動し、TypeScript compiler API を使う。Node.js 22 LTS 以上は Next domain target が存在し、adapter を実行するときだけ要求する。
  3. component identity は repository-relative module path と exported component name。default export は stable exported name metadata を持ち、route path は identity ではなく attribute とする。
  4. Node adapter は `code-structure-viz.next-adapter/v1` request/response JSON を stdin/stdout で交換し、Python core が `code-structure-viz.semantic/v1` envelope へ格納する。
  5. I05-AT-001 を含む acceptance suite で observable result を確認します。
    6.
