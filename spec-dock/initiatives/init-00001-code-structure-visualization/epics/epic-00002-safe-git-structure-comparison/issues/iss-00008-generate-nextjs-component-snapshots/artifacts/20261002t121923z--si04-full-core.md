## 7. full D と model semantics

`resolve_discovered_v3()` を source ownership/identity の基盤として使用しますが、SI-04 はそこで止まりません。

内部で collection ごとの full D view を構成します。

```text
D.projects    = request reconstructed Projects (full file_ids)
D.files       = request reconstructed Files without content_base64
D.modules     = published + proof-only resolved Modules
D.components  = published + proof-only Components
D.members     = published + proof-only Members
D.relations   = published + proof-only Relations
D.facts       = published + proof-only Facts
```

この D を **validation-only full model** に変換します。これは公開 model ではありません。Project は acquired full membership を保持し、coverage は caller の値を使わず actual D から validation 用に構築します。

full D と public safe M の両方に、変更されていない semantic grammar を適用します。

`validate_model()` を利用する場合、SI-04 の stage-2/3 semantic validation中に 10,000 cap へ早期 routing させないよう、validation-only call の `max_model_records` には request の `max_total_array_items` 等、**model-record routing より広い既存 structural cap** を使用します。actual `max_model_records` 判定は stage 5 で一度だけ行います。

この call で少なくとも次を再検証します。

| semantic surface | 必須確認 |
|---|---|
| Project | root/config/source-root containment、config digest、identity |
| File | project/path/roles/effective-role |
| Module | project/path、program owner、router/client/derived roles |
| Component | Module ownership、declaration identity |
| Member | export/import/prop semantics |
| PropsTypeIR | full grammar、depth/nodes/properties/union/intersection/signature limits、type parameter scope |
| repository type ref | full D では D Module、public M では public Module に限定 |
| Relations | target kinds、roles、boundary semantics |
| Facts | Module value と exact correspondence |
| boundary roles | semantic graph から再導出 |
| diagnostics/coverage | actual semantic state と一致 |

SI-03 の Props walker は D/M reference ID closure に引き続き利用できますが、**`_validate_type_node()` / `validate_model()` が full grammar・canonicality・budget・scope の certificate** を担当します。

## 9. post-acquisition locality: 旧 `SourceFailureLedger` を偽装せず意味を再利用する

ここは SI-04 の重要な実装判断です。

旧 `SourceFailureLedger.__post_init__()` は次を要求します。

```text
failures == source_seal.source_view["read_failures"]
```

一方、production `SourceAcquisitionSeal` は complete-only であり、成功 seal の `source_view.failures` は空でなければなりません。

SI-04 の `parse_file` / `read_file` roots は **取得済み frozen bytes に対する post-acquisition semantic observations** です。したがって、それらを `source_view.read_failures` に見せかけて旧 ledger を生成することは仕様違反です。

### v3-local solution

`derive_post_acquisition_locality_v3()` を Core validation module 内に実装します。新しい public failure type や wire field は作りません。

入力は次だけです。

```text
exact SourceAcquisitionSeal
full-proof-validated parse_file/read_file roots
request targets
derived source partition
```

実装は同じ complete seal の `final_plan["source_graph"]` を読みます。graph を caller から受けません。

graph identity を再確認します。

```text
graph_digest == digest(nodes/edges/open_edges)
graph_digest == seal.source_view.source_graph_digest
all graph node content_sha256 == same seal.source_view frozen file sha256
```

これは `SourceAcquisitionSeal` 自身が既に検証している invariant ですが、Core validator 側でも locality の入力 owner を明示的に join します。

locality calculation は旧 `SourceFailureLedger` の accepted wire-independent meaning を保持します。

| calculation | v3-local meaning |
|---|---|
| failed start | validated post-acquisition File root の path に一致する source graph node |
| forward closure | failed node が依存する resolved descendants |
| reverse closure | failed node に到達可能な importers。これが failure closure |
| safe source candidates | reverse closure に含まれない acquired source paths |
| selected-target taint | target が failed/forward/reverse affected region に触れる |
| open edge | affected regionからの open dependency があれば isolation を認定しない |
| `module_plane` uncertainty |旧 ledger 同様、保守的に locality 不成立 |
| result | localized / nonlocal の internal Core evidence |

さらに、normal partial-safe success では SI-03 の safe File projection が failure reverse-closure を公開していないことを確認します。

この v3-local locality evidence は immutable bytes/digest として Core decision の内部 measurement に保持して構いませんが、SI-05 の public record に新 key として出しません。

結果 routing は既存のみです。

```text
localized     -> semantic failure may remain partial_safe
nonlocal      -> CSV-NEXT-SOURCE-003 / payload_unavailable
```

`CSV-NEXT-SOURCE-001` の acquisition ledger certificate を捏造せず、`SourceFailureLedger`、`source_view.read_failures`、seal bytes を変更しません。

## 10. selected missing/component-only/duplicate exceptional branch

SI-03 normal seam の `full_module_owners_v3()` は、正常 base で acquired program File ごと一 Moduleを要求します。これを弱めてはいけません。

しかし accepted contract は selected target についてのみ次の例外を保持します。

```text
missing
component_only
byte-identical duplicate
```

これらは **完全proof base を検証した後の TARGET-001 / no payload 専用例外**です。

### closed exceptional route

Core validator は normal SI-03 seam を作る前に、raw selected target の cardinality failure を検査します。

```python
failure = target_completeness_failure(validation_model, request["targets"])
```

failure がない場合は strict normal route に進みます。

failure がある場合、旧 narrow helpers の意味だけを再利用します。

```text
_target_missing_module_exceptions
_target_duplicate_module_exceptions
```

そのうえで v3-specific exceptional proof validator が次を全て確認します。

| check | rule |
|---|---|
| source Projects/Files | same request の全取得 source IDs が D に exact once |
| missing Module | selected program File に限る |
| component-only | expected canonical Module ID への orphan Component だけを限定許可 |
| duplicate | selected key の **byte-identical** Module rows だけ |
| unrelated Module gap |拒否 |
| inconsistent duplicate |拒否 |
| proof-only source | parent reconstruction |
| other semantic records | ID/ownership/type/ref 全検証 |
| roots/seeds/edges/taints | full exact proof |
| export witnesses | full validation |
| target rows | exact failure reason |
| unrelated dangling ref |拒否 |
| unrelated invalid proof | target failure より先に protocol invariant rejection |

byte-identical duplicate の raw model は validation copy だけで deduplicate し、unique D と照合します。元 payload を書き換えません。

missing/component-only では、expected missing Module ID だけを allowed missing reference として validation copy に渡します。任意の proof dangling ID へ一般化しません。

この exceptional route では **`retain_source_inventory_seam_v3()` を呼びません**。normal source seam/partition を available success として mint しないためです。

成功結果は:

```text
ValidatedSemanticDecisionV3
  gate = TARGET-001 / payload unavailable
  source_inventory_seam = None
  compatibility-v3 = retained
  entity measurement = None
  model-record routing = 未実行
```

とします。

normal source seam の `full_module_owners_v3()` を変更・exception parameter 追加・global relaxationしてはいけません。

## 15. record/entity budget

actual model-record count は既存 `response_model_record_counts()` semantics を使用できます。
