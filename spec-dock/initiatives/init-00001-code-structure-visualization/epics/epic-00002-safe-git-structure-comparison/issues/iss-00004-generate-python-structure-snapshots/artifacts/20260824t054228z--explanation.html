ISSUE-01 Generate Python Structure Snapshots

coding agent または人間が、対象 Python repository を実行せずに class 構造を semantic JSON と PlantUML で取得できる。

ISSUE-01 は package stable key です。actual SpecDock issue ID は adoption 時に割り当てられ、baseline に production path/symbol は未実装です。
図を読み込んでいます。

この資料で理解できること

この HTML だけで、対象 scope の目的、責務、正常時と失敗時の動作、データと出力、実装順、検証、対象外を把握できます。Requirement、Design、Plan の要約ではなく、新規参加者向けに契約を一続きで説明する specification Artifact です。

製品が HTML report を生成する機能ではありません。ブラウザ内 PlantUML は、この仕様説明の理解を助けるためだけに使用します。

背景と解決したい問題

  • coding agent として、変更前の構造や調査対象 class の周辺を機械可読かつ図示可能な形で把握し、source 全文を外部 Artifact へ複製せずに実装判断へ使いたい。
  • この Issue は python / snapshot を一つの observable acceptance boundary として所有します。
  • declared dependency は ありません。unfinished sibling の内部実装へ依存しません。
  • public CLI、versioned semantic schema、Artifact redaction、後続全 adapter が依存する common foundation を同時に導入し、公開後の破壊的変更からの回復が難しいため strict を選ぶ。

正常時の処理

      
    
        
  1. 利用者が次の command boundary を使います: code-structure-viz snapshot --repo . --domain python --output-dir /tmp/csv-python-snapshot
  2. target 無指定では ignore と scope 設定を適用した repository 内の全 `.py` source を snapshot 対象とする。
  3. class identity は normalized module path と qualified class name の組である。nested class は outer class を含む qualified name を持つ。
  4. semantic JSON は `code-structure-viz.semantic/v1` envelope、domain `python`、document kind `snapshot` を持つ。
  5. I01-AT-001 を含む acceptance suite で observable result を確認します。

失敗時と境界条件

      
条件観測される動作利用者が確認する点
failure 1repository、Python version、config、output collision の core preflight failure は Artifact を公開せず exit 1 または 2 とする。status、exit、manifest diagnostic、既存 output の不変性
failure 2一部 source の parse/read failure で安全な残りを表現できる場合は domain `incomplete`、成功した Artifact と diagnostic を保持し exit 3 とする。status、exit、manifest diagnostic、既存 output の不変性
